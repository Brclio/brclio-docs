BEFORE YOU START

先弄懂，你将得到什么。

别人发到 hello@你的域名 的邮件，经 Cloudflare 转交，落进你原来的 Gmail、Outlook 或 QQ 邮箱。你继续用原来的邮箱看信；对外可以展示自己的域名地址。

域名

这份名字按年持有。注册与续费需要付费，金额以结账页为准。

Email Routing

接收并转发来信。基础转发可免费使用，域名需要使用 Cloudflare DNS。

现有邮箱

最终存放和阅读邮件的地方。准备一个你能正常登录、能收验证邮件的邮箱。

先记住这一点

收信转发配置完成，不等于已配置域名发信。直接在原邮箱点“回复”，发件地址可能仍是原邮箱。想用域名地址回复，继续读发信方案。

  • 准备一个已验证邮箱的 Cloudflare 账号，以及购买页面支持的付款方式。
  • 准备真实姓名、电话、地址等注册人资料；当前注册联系人字段要求 ASCII 字符，可使用姓名拼音和英文地址。
  • 本教程面向新域名。已有企业邮箱的域名，先读已有 MX 记录怎么办，再操作接入。

依据：域名注册要求 · Email Service 定价。

01
A NAME OF YOUR OWN

买下你的域名。

这里先完成“拥有名字”，再为它配置邮件。

1

找到注册入口，搜索完整域名

帐户后台 → 域名 → 注册 → Buy domain

进入 dash.cloudflare.com 并选择正确帐户。点击 Buy domain 后，在“注册域名”页面输入名字，按 Enter 搜索；英文界面可能显示 Register domains / Search。

优先挑容易拼、容易念的名字，核对后缀。当前 Registrar 不支持国际化域名（IDN）；若搜索不到，尝试另一名字或受支持的后缀。

2

同时看注册价格和续费价格

确认拼写，再进入目标域名的购买流程。

相似结果的后缀可能不同：.com 和 .com.co 是不同域名。点击目标域名卡片进入核对页；部分界面也会显示“立即购买 / Purchase”，系统还会再次检查可注册状态。

3

核对订单，填写注册人信息

先分清联系人资料、邮箱验证和证件核验。

  • 名字：逐字核对完整域名和后缀。
  • 年限：确认购买几年，查看到期日期与总价。
  • 续费：后台新注册默认开启自动续订，留意续费价格。
  • 联系人：填自己的完整、准确资料；各字段的填写方式见下方。
  • 付款：查看最终金额和协议，确认后完成付款。

当前中文界面先显示“继续支付 … 的费用”；后续以实际付款页面为准。官方流程中的最终确认按钮名为 Complete purchase。

下单前检查

域名注册和续费完成后不可退款，买错拼写也不例外。域名由 Cloudflare Registrar 管理期间，需要使用 Cloudflare 域名服务器。

需要身份证实名核验吗？

本教程展示的 .com 购买流程没有身份证上传或人脸核验步骤。填写注册联系人、验证邮箱，与上传证件实名核验是不同环节。Cloudflare 仍要求完整、准确的联系人资料；WHOIS 隐私保护会隐藏多数公开联系信息，但 Cloudflare 保留未隐藏的注册记录，因此不能把它称为“匿名注册”。

依据：官方联系人要求 · WHOIS 隐私说明。具体要求仍以所选后缀和当时页面提示为准。

注册人信息，一项一项怎么填

名字 / 姓氏
填写注册人的名和姓。当前字段仅接受 ASCII 字符；中文姓名可用拼音，分别填入对应位置。
电子邮件
填写自己能正常收信的邮箱，用于注册联系和验证。刚买的域名还没配好邮件时，先用现有邮箱。
组织（可选）
按实际注册主体填写。个人注册且没有组织信息时可留空。
电话
选择与电话号码匹配的国家区号，再填写可联系到你的号码；不要照抄截图里的区号和号码。
国家 / 地区
按自己的联系地址选择。该选择会影响省 / 州、邮编等后续字段。
地址 / 地址 2
用英文或拼音填写实际联系地址。地址 2 用于补充楼层、房间等信息，没有补充可留空。
城市 / 省或州 / 邮编
分别填写与该地址对应的内容，核对国家、城市、省或州和邮编是否匹配。
4

买完后，确认“域名真的归你了”

购买确认、联系人验证和续费检查，各有作用。

  1. 查看域名管理页。确认新域名出现在注册列表，并收到注册确认邮件。
  2. 查看注册人邮箱。若收到联系人验证通知，按邮件完成验证；账号邮箱验证与注册人邮箱验证不是同一件事。若被要求验证，请立即完成；未在 15 天内验证可能导致域名暂停解析。
  3. 记下到期日。确认付款方式有效；自动续费首次尝试一般在到期前约 30 天，不要等最后一天才处理。

依据：注册流程 · 注册人邮箱验证 · 域名续费 · 退款说明。

02
A NEW ADDRESS, SAME INBOX

让域名邮件，走进原来的邮箱。

用 Email Routing 免费转发，先从一个 hello 地址开始。

HOW IT WORKS

换一个对外地址，保留熟悉的收件箱。

朋友发送邮件hello@example.com
→
CloudflareEmail Routing
→
你打开原来的邮箱Gmail / Outlook / QQ

example.com 是说明用域名，操作时换成你真正持有的域名。

1

进入“电子邮件路由”

计算 → 电子邮件服务 → 电子邮件路由

英文对应 Compute → Email Service → Email Routing。选择“接入域名 / Onboard Domain”。若看到的是旧版导航，可在后台搜索 Email Routing；本教程截图使用当前中文界面。

2

选择域名，审阅 DNS 后激活

把“这个域名的信送到哪里”告诉 DNS。

选择自己的域名，点“继续”。页面会列出将添加的记录。确认后，当前中文界面点“激活”；官方英文入门文档也使用 Done 描述完成接入。

这三类记录，各管一件事

MX
把发给你域名的邮件交给 Cloudflare 收信服务器。
TXT / SPF
声明哪些服务器可以代表域名发送或转发邮件。
TXT / DKIM
提供签名验证所需的公钥，帮助接收方验证转发邮件。

服务器、优先级、selector 与公钥都以你自己的后台为准。截图里的数值用于识别字段，不需要逐项照抄。激活后回到对应域名的 Settings，检查 MX、SPF、DKIM 状态；Locked 表示由服务管理，并非报错。

已经用着企业邮箱？

先不要替换现有 MX。同一个收信域名不能简单同时交给原企业邮箱和 Routing。先决定由谁收信，再做迁移；也可以研究使用独立子域名。不要为了让向导变绿就删除业务记录。

已有 SPF，该怎么处理？

＋

同一个名称只能有一条以 v=spf1 开头的 SPF 记录。已有其他发信服务时，应将需要保留的授权合并进同一条记录，而不是新加第二条。下方是 Routing 常见授权片段，完整值以后台和现有服务配置为准。

include:_spf.mx.cloudflare.net

DKIM 公钥无需从教程复制。查看官方域名配置说明 ↗

3

添加现有邮箱，并完成验证

电子邮件路由 → 目标地址 / Destination Addresses

填入你最终用来收信的邮箱，点击“添加地址”。然后去这个邮箱打开 Cloudflare 发来的验证邮件，点击 Verify email address，再返回后台检查“已验证 / Verified”。

找不到验证邮件时，先查垃圾箱，并检查输入是否有拼写错误。未验证的目标地址不能正常启用转发规则。

4

创建 hello → 现有邮箱 的规则

选择域名 → Routing Rules → Create routing rule

按下面三项填写后保存，并检查规则处于 Active / 已启用。这是按官方说明整理的填写表，不是后台截图。

Email pattern
填 hello，选择自己的域名；这里只填 @ 前的部分。
Action
选择 Send to an email（发送到邮箱）。
Destination
选择刚刚验证过的现有邮箱。
TRY YOUR ADDRESS

先把你的规则写清楚

填入域名和前缀，生成对应示例。这里仅在本页生成文本，不会修改 Cloudflare 设置。

hello@example.com

Email pattern：hello · 域名：example.com · Destination：你已验证的现有邮箱

example.com 仅作格式示例，请换成自己的域名。

初次配置先建立一个明确地址即可。Catch-all（全收）会接收所有未明确匹配的地址，包括拼错的名字；它是可选项。

依据：Routing 入门 · 目的地址与路由规则 · SPF 冲突排查。

03
THE FIRST HELLO

收到第一封信，才算配好了。

保存成功只是开始，实际投递才是验收。

  1. 换一个发件邮箱。让另一个邮箱给新地址发送一封纯文字测试信。它要与转发目的邮箱不同，避免部分邮箱服务丢弃自己转给自己的邮件。
  2. 查目标收件箱。核对主题与正文，同时查看垃圾箱。新 DNS 通常数分钟生效，官方提示一般 5–15 分钟，全球传播可能需要 24 小时。
  3. 没收到就看日志。到 Routing 对应域名的 Activity log / 邮件日志查这封信，再看规则、目的地址、DNS 和投递错误。
建议测试主题
我的第一封域名邮件

正文写一句“如果你看到这封信，说明转发已经到达”。先用短邮件验证，再测试日常附件。

已检查 0 / 6 项

清单仅保存在当前浏览器；勾选代表你的人工确认。

依据：测试转发 · 邮件日志说明。

04
AND IF YOU WANT TO REPLY

还想用这个地址发信？

先按用途选择，再单独完成发信验证。

A

只接收注册通知、联系邮件

目前的免费 Routing 就覆盖这个目标。若从原邮箱回复，发送前检查“发件人”字段；它不会因为设置了转发就自动变成域名地址。

B

日常办公，希望稳定收发与回复

选择支持自定义域名的完整邮箱服务。按服务商向导验证域名、配置收信 MX 与 SPF / DKIM / DMARC，再登录其网页邮箱或邮件客户端。若迁移收信，先规划好原 Routing 的停用与 MX 切换。

如果沿用当前收件箱并添加“以此地址发送 / Send mail as”，仍需发信服务提供可用的 SMTP 凭据和域名验证；具体是否支持以邮箱服务商为准。

C

应用通知、验证码等事务邮件

Cloudflare 当前另有 Email Sending Beta，支持 Workers、REST API 和 SMTP。向任意收件人发送需要 Workers Paid，并单独接入 Sending 域名；这不属于本教程的免费收信配置。它当前定位于事务邮件，不面向营销群发。

WHEN SOMETHING FEELS OFF

卡住时，从这里找答案。

已经启用，为什么一直收不到？

＋

按顺序检查：地址拼写 → 目的邮箱是否已验证 → 规则是否 Active → DNS 是否无冲突 → 邮件日志 → 目的邮箱垃圾箱。测试信必须从另一个邮箱发出。刚配置好可等 DNS 传播后重试。

日志里的状态，分别是什么意思？

＋
Forwarded
已转发；没看到时再查目的邮箱的垃圾箱和筛选规则。
Dropped / Rejected
邮件被丢弃或拒收，展开日志查看规则、认证结果与原因。
Delivery failed
投递到目的服务器失败，按目标服务器返回的错误处理。

查看完整日志说明 ↗

可以转发给多人，或者收大附件吗？

＋

基础规则对应一个目标邮箱；更复杂的多人转发可使用 Worker。当前入站邮件上限为 25 MiB，计算的是整封邮件大小，附件编码后会变大，因此不能按“25 MB 附件”理解。详见官方限制。

域名买好后，必须先建一个网站吗？

＋

邮件教程的前提是域名使用 Cloudflare DNS，再设置 Routing。邮件与网站使用不同的 DNS 记录；可以先完成邮件配置，网站之后再做。

没有上传身份证，就等于匿名注册吗？

＋

不等于。本教程截图中的 .com 流程未出现上传身份证或人脸核验，但仍要填写注册联系人资料并完成要求的邮箱验证。注册局允许时，Cloudflare 会隐藏公开 WHOIS 中的大部分个人联系资料；省 / 州、国家等信息仍可能公开，Cloudflare 也仍保留完整记录。详见WHOIS 隐私说明。

停止使用时，需要做什么？

＋

先把重要账号的联系邮箱改到仍可用的地址，再迁移或停用路由。若不续费域名，至少在到期前 30 天处理自动续费设置；域名失效后，依赖它的收信和找回密码流程也会受影响。
