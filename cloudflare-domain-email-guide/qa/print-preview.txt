 1     找到注册入口，搜索完整域名

02 让域名邮件，走进原来的邮箱。
          用 Email Routing 免费转发，先从一个 hello 地址开始。

     HOW IT WORKS

     已经用着企业邮箱？
     先不要替换现有 MX。同一个收信域名不能简单同时交给原企业邮箱和 Routing。先决定由谁收信，再
     做迁移；也可以研究使用独立子域名。不要为了让向导变绿就删除业务记录。


已有 SPF，该怎么处理？
同一个名称只能有一条以 v=spf1 开头的 SPF 记录。已有其他发信服务时，应将需要保留的授权合并进同一条
记录，而不是新加第二条。下方是 Routing 常见授权片段，完整值以后台和现有服务配置为准。
     include:_spf.mx.cloudflare.net



DKIM 公钥无需从教程复制。查看官方域名配置说明 ↗

 3      添加现有邮箱，并完成验证
         电子邮件路由 → 目标地址 / Destination Addresses

填入你最终用来收信的邮箱，点击“添加地址”。然后去这个邮箱打开 Cloudflare 发来的验证邮件，点击
Verify email address，再返回后台检查“已验证 / Verified”。
后台实拍 填写的是你已有的收件邮箱，不是刚准备创建的 hello 地址。

找不到验证邮件时，先查垃圾箱，并检查输入是否有拼写错误。未验证的目标地址不能正常启用转发规则。
 4       创建 hello → 现有邮箱 的规则
         选择域名 → Routing Rules → Create routing rule

按下面三项填写后保存，并检查规则处于 Active / 已启用。这是按官方说明整理的填写表，不是后台截图。

Email pattern            填 hello ，选择自己的域名；这里只填 @ 前的部分。
Action                   选择 Send to an email（发送到邮箱）。
Destination              选择刚刚验证过的现有邮箱。

           THE FIRST HELLO
03 收到第一封信，才算配好了。
           保存成功只是开始，实际投递才是验收。
01 换一个发件邮箱。让另一个邮箱给新地址发送一封纯文字测试信。它要与转发目的邮箱不同，避免部分邮
   箱服务丢弃自己转给自己的邮件。
02 查目标收件箱。核对主题与正文，同时查看垃圾箱。新 DNS 通常数分钟生效，官方提示一般 5–15 分钟，

   全球传播可能需要 24 小时。
03 没收到就看日志。到 Routing 对应域名的 Activity log / 邮件日志查这封信，再看规则、目的地址、DNS 和

   投递错误。

    AND IF YOU WANT TO REPLY
04 还想用这个地址发信？
    先按用途选择，再单独完成发信验证。


A   只接收注册通知、联系邮件
    目前的免费 Routing 就覆盖这个目标。若从原邮箱回复，发送前检查“发件人”字段；它不会因为
    设置了转发就自动变成域名地址。


B   日常办公，希望稳定收发与回复
    选择支持自定义域名的完整邮箱服务。按服务商向导验证域名、配置收信 MX 与 SPF / DKIM /
    DMARC，再登录其网页邮箱或邮件客户端。若迁移收信，先规划好原 Routing 的停用与 MX 切
    换。
    如果沿用当前收件箱并添加“以此地址发送 / Send mail as”，仍需发信服务提供可用的 SMTP 凭
    据和域名验证；具体是否支持以邮箱服务商为准。


C   应用通知、验证码等事务邮件
    Cloudflare 当前另有 Email Sending Beta，支持 Workers、REST API 和 SMTP。向任意收件人
    发送需要 Workers Paid，并单独接入 Sending 域名；这不属于本教程的免费收信配置。它当前
    定位于事务邮件，不面向营销群发。
    查看 Cloudflare 发信入门 ↗

          WHEN SOMETHING FEELS OFF
? 卡住时，从这里找答案。
已经启用，为什么一直收不到？
按顺序检查：地址拼写 → 目的邮箱是否已验证 → 规则是否 Active → DNS 是否无冲突 → 邮件日志 → 目的邮箱
垃圾箱。测试信必须从另一个邮箱发出。刚配置好可等 DNS 传播后重试。
日志里的状态，分别是什么意思？

Forwarded                已转发；没看到时再查目的邮箱的垃圾箱和筛选规则。
Dropped / Rejected       邮件被丢弃或拒收，展开日志查看规则、认证结果与原因。
Delivery failed          投递到目的服务器失败，按目标服务器返回的错误处理。

查看完整日志说明 ↗

可以转发给多人，或者收大附件吗？
基础规则对应一个目标邮箱；更复杂的多人转发可使用 Worker。当前入站邮件上限为 25 MiB，计算的是整封
邮件大小，附件编码后会变大，因此不能按“25 MB 附件”理解。详见官方限制。
域名买好后，必须先建一个网站吗？
邮件教程的前提是域名使用 Cloudflare DNS，再设置 Routing。邮件与网站使用不同的 DNS 记录；可以先完成
邮件配置，网站之后再做。
注册资料会公开吗？
注册局允许时，Cloudflare 会隐藏多数个人联系资料，但省 / 州和国家等信息仍可能公开。隐私处理不是匿名
注册，联系人信息仍须真实。详见WHOIS 隐私说明。
停止使用时，需要做什么？
先把重要账号的联系邮箱改到仍可用的地址，再迁移或停用路由。若不续费域名，至少在到期前 30 天处理自动
续费设置；域名失效后，依赖它的收信和找回密码流程也会受影响。
